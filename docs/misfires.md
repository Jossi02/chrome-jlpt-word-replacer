## 분류별 기록

### 1. 오탐 (엉뚱한 곳이 치환됨) — 담당: C(사전) → **D3-2에서 전부 해결 완료**

#### 1-1. 「바람」— 관용구 "-하는 바람에" 오치환 — ✅ 해결(규칙 예외)
- **위치**: 위키백과(라이브·백업 동일) 「국호」단락 — `...으로 잘못 기록하는 바람에, 결국 나라 이름이 되었다.`
- **문제**: "-하는 바람에"(~하는 결과로, 원인)는 문법화된 관용 표현인데 명사 「바람」(날씨의 바람)으로 인식해 風(かぜ)로 치환함.
- **참고**: 같은 「바람」이 블로그 기사에서는 `달콤한 복숭아 향기가 바람을 타고 흘러왔다`처럼 **정확히** 번역됨 — 단어 자체가 아니라 관용구 문맥에서만 발생하는 오탐. 규칙(조사/경계)으로는 못 잡는 유형.
- **해결**: 사전에서 빼지 않고 `src/matcher.js`에 좁은 예외를 추가 — 「바람」 바로 앞이 "는 "이고 바로 뒤 조사가 "에"일 때만 매치를 건너뛴다. 74쌍·§5.3 등 기존 규칙은 전혀 안 건드림. `tests/matcher.test.mjs`에 회귀 테스트 2개 추가(관용구는 안 잡히고, "바람이 분다"/"바람을 타고"는 그대로 잡힘). 실브라우저 재검증: 위키(라이브)에서 사라짐, 블로그에서는 그대로 유지 확인.

#### 1-2. 「사전」— 동형이의어(事前 vs 辞書) 오치환 — ✅ 해결(엔트리 삭제)
- **위치**: 위키백과(라이브·백업 동일) 「선거」단락 — `...지금까지 6번 실시되었다. 사전 투표는 선거일 5일...`
- **문제**: 여기서 「사전」은 "미리/사전(事前)"인데 사전 엔트리는 「辞書(じしょ, 사전=책)」으로만 등록돼 있어 오치환.
- **해결**: "사전 투표/예약/신청"류 관용 표현이 매우 흔해 국소 규칙으로 못 거르는 유형으로 판단, `data/dictionary.json`에서 id 119 엔트리(辞書/사전) 전체 삭제. `python tools/build_dictionary.py` 재생성 확인(646엔트리, 불변식 8종 통과).

#### 1-3. 「상의」— 형태소 결합(위 + 의) 오치환 — ✅ 해결(별칭 제거)
- **위치**: 위키백과(라이브·백업 동일) 「지리」단락 — `...최동단은 동해 상의 독도, 서단은 압록강...`
- **문제**: "동해 상(上)의"(동해 위에 있는)에서 "상"+조사 "의"가 우연히 사전 표제어 「상의」(上着/윗옷)와 같은 문자열이 되어 오치환.
- **해결**: 겉옷 엔트리(id 21)의 `match` 배열에서 "상의" 별칭만 제거(겉옷 자체는 그대로 유지, 손실 없음).

#### 1-4. 「고려」— 동형이의어(考慮 vs 高麗) 오치환 — ✅ 해결(엔트리 삭제)
- **위치**: 위키백과(라이브·백업 동일) 「국호/어원」단락 — `...명칭의 어원은 중세 국가인 고려(高麗)에서 유래하였다.`
- **문제**: 나라 이름 「고려」(高麗, 고려 왕조)가 사전 엔트리 「考慮(こうりょ, 숙고)」와 겹쳐 오치환. 백과사전·역사 콘텐츠에서 재발 가능성 높음.
- **해결**: `data/dictionary.json`에서 id 610 엔트리(考慮/고려) 전체 삭제. 국소적으로 구분할 신호가 없어(고유명사 vs 일반명사) 규칙 수정 대신 삭제 선택.

**사전 규모 변화**: 648 → **646**(사전·고려 삭제, 상의는 별칭만 제거라 카운트 불변) · N5 328→327 · N1 50→49 · ruby대상 544→542 · 매칭표면형 680→677. `tests/dictionary.test.mjs` 하드코딩 수치 전부 갱신, `npm test` 33/33 통과. 브라우저 재검증(확장 새로고침 후): 위키(라이브) 200개 치환 중 4개 전부 사라짐, 블로그 52개 치환 중 「바람」(정상 용례)은 그대로 유지, 콘솔 에러 0.

## 참고 관찰 (버그 아님, 기록용)

- **200개 상한 도달**: N1/밀도100%(가장 공격적인 조건)에서는 위키백과가 라이브·백업 모두 정확히 200개(`MAX_REPLACEMENTS` 상한)에서 멈춤. 이전 D1-B1 실측 161개는 다른 레벨/밀도 조건이었던 것으로, 상한 자체는 의도된 동작(G11) — 버그 아님.
- **로컬 백업 위키 테스트의 함정**: `demo/backup/wiki.html`을 `localhost:8000`으로 열면 `scope.js`의 `SITE_ROOTS`가 `doc.location.hostname === ko.wikipedia.org`로 판단하기 때문에 **위키 전용 규칙(`.mw-parser-output` 우선 선택 + 인포박스/표 제외)이 적용되지 않는다.** 실제로 로컬 백업에서는 인포박스 표 데이터(`지도이름주민등록인구...`)까지 치환 대상에 들어가는 것을 확인했으나, **같은 문서를 라이브 `ko.wikipedia.org`에서 열면 이 표 데이터 치환은 사라진다**(정상). D3-4 발표 리허설에서 네트워크를 끄고 백업으로 시연할 경우 인포박스에 예상 밖 치환이 보일 수 있다는 점을 팀이 미리 알고 있어야 함 — 코드 수정 대상은 아님(백업은 애초에 최후 수단).
- 다음뉴스 페이지의 "자동요약" 안내 위젯 문구(`기사 제목과 주요 문장을 기반으로...`)가 `<article>` 태그 내부에 있어 스캔 대상에 포함됨. 오역은 아니고 UI 텍스트까지 치환 대상이 되는 점만 참고.
